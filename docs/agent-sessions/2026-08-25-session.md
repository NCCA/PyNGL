# 2026-08-25 -- PySideEventHandlingMixin key handling

## Goal

Escape was hiding the OpenGL viewport and leaving the surrounding window behind
in any application that mixes `PySideEventHandlingMixin` into a `QOpenGLWidget`
rather than a `QOpenGLWindow`. Found whilst porting BulletNGL to MuJoCo in
PyNGLDemos; `MassSpring` in that repo had the same bug already.

## Root cause

`keyPressEvent` called `self.close()` on Escape. In a `QOpenGLWindow` that is
the top level thing and closing it closes the application, which is what the
docstring promises. In a `QOpenGLWidget` inside a `QMainWindow` it closes the
child widget, so the viewport disappears and the panel stays.

The obvious `self.window().close()` does not work: `QOpenGLWindow` is a
`QWindow`, not a `QWidget`, and has no `window()` method at all, so that would
break the 52 window-based demos.

## Files changed

- `src/ncca/ngl/opengl/pyside_event_handling_mixin.py`
  - `close_target()` walks up to the top level where there is one to walk up to
  - `setup_event_handling(handle_key_shortcuts=True)` lets an application that
    owns its keyboard decline Escape, W, S and Space
  - W and S set `self.wireframe` as well as calling `glPolygonMode`, which is
    otherwise overwritten by any `paintGL` that sets the polygon mode itself.
    Only defaulted when the application has not already made it its own.
- `tests/test_pyside_event_handling_mixin.py` -- 7 new tests
